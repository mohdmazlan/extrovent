# Spec Delta

## Purpose

Gives every outdoor entity (posts, places, events, activities, business profiles, chatrooms) a stable non-sequential UUID identity so ids are safe to expose, generate distributedly, and never reveal creation order.

## ADDED Requirements

### Requirement: Entity PKs are app-generated UUIDs
Entity tables SHALL use `CHAR(36)` UUID primary keys generated by the application at create time: `posts.post_id`, `place.id`, `events.event_id`, `activity.id`, `business_profile.id`, `chatroom.room_id`. No entity PK SHALL be auto-increment.

#### Scenario: New post gets a UUID
- **WHEN** an authenticated user creates a post
- **THEN** the response contains a `post_id` that is a UUID string, not a number

#### Scenario: New place gets a UUID
- **WHEN** an authenticated user creates a place
- **THEN** the stored `place.id` is a UUID string generated server-side

### Requirement: Entity ids are opaque strings in the API
All API inputs, outputs, and route params for entity ids (`post_id`, `place_id`, `event_id`, `activity_id`, `room_id`, `business_profile_id`) SHALL be UUID strings. Clients SHALL treat them as opaque strings and SHALL NOT assume numeric ordering.

#### Scenario: Post detail by UUID
- **WHEN** a client requests a post with its UUID `post_id`
- **THEN** the system returns that post regardless of when it was created

#### Scenario: Non-numeric id is not rejected as malformed
- **WHEN** a client passes a well-formed UUID as `event_id`
- **THEN** the system accepts it exactly as it would any valid id

### Requirement: Link tables keep auto-increment keys
Pure join tables (`post_like`, `post_comment`, `event_like`, `participants`, `friends`, `chatroom_members`, `event_image`, `place_image`, `post_image`, `activity_image`) SHALL keep `INT AUTO_INCREMENT` primary keys and SHALL NOT be converted to UUID.

#### Scenario: Like row uses numeric key
- **WHEN** a user likes a post
- **THEN** the `post_like` row is created with an auto-increment `id` while referencing the post by UUID `post_id`

### Requirement: FKs reference UUID entity ids
Every foreign key pointing at an entity PK SHALL be `CHAR(36)` matching the entity id type: `post_image.post_id`, `post_like.post_id`, `post_comment.post_id`, `place_image.place_id`, `place_rating.place_id`, `event_image.event_id`, `event_like.event_id`, `event_comment.event_id`, `event_rating.event_id`, `events.place_id`, `posts.place_id/event_id/activity_id`, `chat_message.room_id`, `chatroom_members.room_id`, `participants.event_id`, `invite.event_id`.

#### Scenario: Post image links by UUID
- **WHEN** an image is attached to a post
- **THEN** `post_image.post_id` stores the post's UUID

#### Scenario: Participant links event by UUID
- **WHEN** a user joins an event
- **THEN** `participants.event_id` stores the event's UUID
